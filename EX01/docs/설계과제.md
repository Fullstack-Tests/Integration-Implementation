# 설계과제 — 외부 OpenAPI 연계 (통합 구현 / S-Link)

## 파트 1. 연계 데이터 구성 (NCS 1)
- **연계 요구사항 분석**: 외부 시스템(`jsonplaceholder` 게시글 API — 기본, 또는 **공공데이터포털 OpenAPI로 교체 가능**)과 우리 시스템 간 연계가 필요한 데이터를 식별합니다. (공공데이터로 교체 시 serviceKey 는 properties 로 분리)
- **연계 데이터 식별·표준화**: 외부 응답 `{userId, id, title, body}` 를 우리 표준 `PostDTO`/`Post(Entity)` 로 매핑합니다.
- 산출물: `연계_요구사항_분석서.md`, `연계(인터페이스)_정의서.md`, `연계(인터페이스)_명세서.md` 를 작성합니다. (포트폴리오 평가)

## 파트 2. 연계 메커니즘 구성 (NCS 2)
- **메커니즘 정의**: `RestTemplate` + `UriComponentsBuilder` 로 외부 API(GET /posts)를 호출하는 연계 메커니즘을 구현합니다.
- **장애·오류 처리(2-2)**: 호출 실패·비정상 상태코드(`ResponseEntity.getStatusCode()`)·응답 null 시 `MyBizException` 을 던지고 `@RestControllerAdvice` 로 일관된 오류 응답을 반환합니다.
- **데이터 보안(2-3)**: 연계 트리거(POST /api/link/sync)는 `ADMIN` 권한, 조회는 인증 사용자만 접근하도록 `SecurityFilterChain` 으로 보호합니다. (외부 API key 가 필요한 API로 교체 시 key 는 `application-dev.properties` 로 분리)

## 파트 3. 내외부 연계 모듈 구현·테스트 (NCS 3)
- **연계 모듈 구현**: 수신(외부 호출·변환·DB 저장) + 재제공(우리 REST API) + 배치(@Scheduled 주기 동기화)를 구현합니다.
- **연계 테스트·검증**: 동기화 정상 동작 / 외부 호출 실패 시 오류 처리 케이스를 테스트합니다.

## 흐름
```
[외부 OpenAPI] --(RestTemplate GET /posts)--> [LinkService 수신·변환]
        --> [Post 저장(JPA, @Transactional)] --> [LinkController 재제공 /api/link/posts]
[LinkScheduler @Scheduled] --(주기)--> LinkService.syncPosts()   ← 배치 동기화
[SecurityFilterChain] --(인가)--> /api/link/sync(ADMIN), /api/link/posts(인증)
```

## 제약
- 추가 라이브러리 없이 Spring 기본 기능만 사용합니다(EAI/ESB·메시지 큐·Spring Batch 미사용).
- RestTemplate 사용(WebClient/WebFlux 미사용), 배치는 `@Scheduled`(Spring Batch 아님).
- 메서드 시그니처 임의 변경 금지. TODO 위치만 채웁니다.
- DataSource·EntityManagerFactory·TransactionManager 는 Spring Boot 자동설정 사용(`@Transactional` 기본).
